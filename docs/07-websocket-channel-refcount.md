# 07. 실제로 연결된 채널이 "연결 끊김"으로 표시됨

- **프로젝트**: kitae1645/mafia42_test
- **원본**: PR [#130](https://github.com/kitae1645/mafia42_test/pull/130) (머지 2026-07-02)
- **스택**: Python 3.12, Chrome DevTools Protocol(CDP) 다중 클라이언트, WebSocket, SQLite + 인메모리 스토어
- **분류**: 상태 집계 / 공유 상태
- **CS 접점**: 여러 관찰자가 하나의 상태를 각자 덮어쓰면, 마지막에 쓴 사람이 이긴다. 참조 카운팅이나 단일 소유자가 필요하다.

## 한 줄 요약

채널 1·2가 UI에서 영구히 "연결 끊김"으로 표시됐다. 원인이 세 개 겹쳤는데, ① 채널 서버 IP가 AWS에서 교체돼 매핑이 실패했고 ② CDP 클라이언트마다 독립적으로 상태를 `disconnected`로 덮어썼고 ③ 초기 감지 결과가 재연결 시점에 지워졌다. IP 갱신 + 모듈 레벨 WebSocket 참조 카운팅으로 해결.

## 증상

- 웹 UI에서 채널 1, 2가 계속 `disconnected`.
- 그런데 게임 클라이언트들은 실제로 그 채널에 WebSocket 연결을 유지하고 있었음(트래픽은 정상).
- 5개 클라이언트 중 3개가 채널 0으로 보고되는 이상한 분포.

## 조사

1. 로그에서 CDP 포트별 채널 판정을 출력 → `port 9223 → channel 1`, `port 9224 → channel 2`가 실제로는 잡히는데 상태가 계속 꺼져 있음. "감지 실패"가 아니라 "감지 후 덮어쓰기"로 방향 수정.
2. `KNOWN_CHANNEL_HOSTS`의 IP 목록과 실제 연결 원격 IP 비교 → 채널 1: `75.2.1.51 → 3.34.190.153`, 채널 2: `75.2.34.7 → 3.36.177.104`로 교체됨. 매칭 실패 시 채널 0으로 폴백하는 코드가 있어 조용히 오답이 됨.
3. 상태 쓰기 지점을 전부 추적 → 각 `CDPClient`가 자기 게임 클라이언트의 WS가 닫히면 곧바로 `store.set_status(ch, "disconnected")` 호출. 다른 포트의 클라이언트가 같은 채널에 살아있는지는 보지 않음.
4. 초기 감지 함수가 `_mark_channel_connected()`로 상태를 켠 직후, 각 클라이언트의 `_connect()`가 `_clear_port_refs`로 같은 채널의 참조를 지워 상태가 다시 꺼지는 순서 문제 확인.

## 원인

세 개의 독립 결함이 같은 증상으로 수렴:

1. **낡은 외부 식별자**: 하드코딩된 IP가 교체되자 조용히 채널 0으로 폴백.
2. **관찰자별 상태 쓰기**: 공유 상태에 대한 last-writer-wins. 다중 클라이언트 구조에서 "내가 끊겼다"는 "채널이 끊겼다"가 아님.
3. **초기화 순서**: 초기 감지 결과가 클라이언트 연결 단계에서 지워짐.

## 해결

- `KNOWN_CHANNEL_HOSTS`에 새 IP 추가
- 모듈 레벨 참조 카운터 도입:

```python
# channel_id -> set[cdp_port]  (해당 채널에 WS를 유지 중인 클라이언트)
_ACTIVE_CHANNEL_WS: dict[int, set[int]] = {}
```

- 채널은 **어떤 클라이언트도** 해당 채널의 WS를 갖고 있지 않을 때만 `disconnected`로 전환
- `_clear_port_refs` 호출 전에 `_ws_map.values()`를 저장하고, 그 클라이언트가 **실제로 보유했던** 채널만 감소
- 보너스: CDP `Runtime.evaluate`로 `window.location.hash`를 읽는 폴백 감지 경로 추가. IP 매핑이 또 틀려도 복구 가능.

## 검증

| 확인 | 방법 | 결과 |
|------|------|------|
| 상태 표시 | PROD 배포 후 5채널 조회 | 전부 `connected` |
| 감지 정확성 | 로그에서 포트-채널 매핑 확인 | `9223 → channel 1`, `9224 → channel 2` |
| 회귀 | 기존 모니터 테스트 | 통과 |

## 재발 방지

- 이중 감지 경로(IP + URL hash): 한쪽이 낡아도 다른 쪽이 맞출 수 있게.
- 상태 전이를 "내 연결"이 아니라 "채널 단위 집계"로만 수행하도록 구조 변경.

## 일반화

- **공유 상태에는 소유자를 하나 두거나, 참조 카운트로 집계하라.** 여러 관찰자가 직접 덮어쓰면 "가장 최근에 끊긴 사람"이 전체 상태를 결정한다.
- **하드코딩된 외부 식별자는 실패할 때 조용하다.** 매칭 실패 시 기본값으로 폴백하는 코드는 반드시 그 사실을 로그로 남겨야 한다. 채널 0 폴백이 없었다면 30분 만에 발견했을 문제다.
- **초기화 순서를 의심하라.** "감지가 안 된다"와 "감지했는데 지워진다"는 로그 모양이 비슷하지만 원인이 정반대다.
