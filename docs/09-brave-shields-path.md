# 09. 브라우저에서만 버튼이 조용히 실패 — 경로가 필터 시그니처가 된 사례

- **프로젝트**: kitae1645/tagVault
- **원본**: PR [#1](https://github.com/kitae1645/tagVault/pull/1) (머지 2026-07-04)
- **스택**: Python 웹앱(FastAPI 계열), 정적 프론트엔드, Brave 브라우저
- **분류**: 브라우저 제약 / 경로 설계
- **CS 접점**: 클라이언트 측 필터는 애플리케이션보다 아래 계층에서 요청을 제거한다. 서버 로그에 아무것도 없다는 사실이 곧 단서다.

## 한 줄 요약

Brave에서 "지금 수집" 버튼이 `ERR_BLOCKED_BY_CLIENT`로 실패했다. 광고·트래커 필터 목록(EasyPrivacy 계열)이 경로에 `collect`가 들어간 요청을 차단했기 때문이며, 차단 패턴과 겹치지 않도록 `/api/collect` → `/api/gather`로 라우트를 개명했다.

## 증상

- Brave 사용자만 버튼 클릭 시 아무 반응 없음. 개발자 도구 콘솔에 `ERR_BLOCKED_BY_CLIENT`.
- **서버 로그에 요청이 전혀 없음.** 4xx도 아니고 연결 자체가 발생하지 않음.
- 다른 브라우저(Chrome/Firefox/Safari)는 정상.

## 조사

1. 서버 로그 침묵 → 애플리케이션 코드 이전 계층. 미들웨어, 프록시, CORS를 차례로 배제.
2. devtools 네트워크 패널에서 요청이 "blocked" 상태로 표시되고, 응답 코드가 없음 → 브라우저가 요청을 만들지 않음.
3. Brave Shields의 필터 목록이 쓰는 패턴을 확인. `/collect`는 Google Analytics 수집 엔드포인트(`/collect`)와 문자열이 같아 `*/collect*` 류 규칙에 걸립니다.

## 원인

우리 라우트 이름이 추적 비콘의 시그니처와 일치했습니다. 필터 목록은 도메인 평판이 아니라 **URL 패턴**으로 동작하므로, 정당한 서비스도 같은 문자열을 쓰면 함께 차단됩니다. 서버 입장에서는 요청이 아예 도착하지 않으니 로그로는 절대 알 수 없습니다.

## 해결

경로 개명. 패턴 충돌을 없애는 것이 목적.

```diff
-@app.post("/api/collect")
+@app.post("/api/gather")
 def collect(...): ...

-@app.get("/api/collect/status")
+@app.get("/api/gather/status")
 def collect_status(...): ...
```

프론트엔드 fetch URL과 테스트도 동시에 수정.

- 함수 이름(`collect`)은 그대로 둠 — 도메인 의미는 유지하고 **외부 노출 문자열만** 바꾸는 쪽이 변경 범위를 최소화합니다.
- 하위 호환 alias를 두지 않았습니다. 남겨두면 차단 패턴이 그대로 살아 있고, 사용자는 여전히 실패합니다.

## 검증

| 확인 | 방법 | 결과 |
|------|------|------|
| 엔드포인트 동작 | `tests/test_web_app.py` (수집 실행, 상태 조회, 쿨다운) | 통과 |
| 프론트 경로 | 정적 페이지에서 fetch URL 갱신 | 정상 호출 |
| 브라우저 | Brave에서 버튼 클릭 | 수집 시작, 차단 없음 |

## 재발 방지

- 새 API 경로를 정할 때 광고·트래커 필터에서 흔히 쓰이는 토큰(`collect`, `track`, `analytics`, `beacon`, `pixel`, `ad`, `stats`)을 피합니다.
- 문제가 재발하면 "서버 로그 0건"을 1차 신호로 삼아 브라우저 차단을 먼저 의심합니다.

## 일반화

- **요청이 없으면 우리 코드 문제가 아니다.** 로그가 비어 있는 장애는 클라이언트, 확장 프로그램, 프록시, DNS, 방화벽 순으로 내려간다.
- **외부에 노출되는 이름은 API 계약이 아니라 시스템과의 계약이다.** 필터, WAF, CDN 규칙이 문자열을 보고 동작한다.
- **호환 alias는 차단 우회가 아니다.** 차단된 경로를 남겨두면 그 경로를 쓰는 클라이언트는 계속 실패한다.
